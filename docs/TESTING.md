# Manual acceptance checklist

The isolated suite also includes personal theme acceptance: settings preview cards, keyboard radio selection, saved theme after reload, cross-tab synchronization, route persistence, two players with different themes, header switching during a live auction, unchanged room state/franchise colours, player/audio dialogs and 360px/390px layouts. Theme screenshots are under `.runtime/theme-ember-*`. Check real Android/iOS system bars and display preferences on devices separately.

Automated checks: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`. Windows may require the `.cmd` npm/npx launchers. Use the lockfile and Node >=22.12. The browser harness launches the local backend/frontend and uses isolated contexts; it must run with development Auth configuration. It creates persistent local test accounts and completed test rooms under `.runtime`.

1. Register/login/logout in two isolated profiles. Refresh a protected URL. Verify identity and room screen restore. Repeat with Supabase email confirmation and token refresh when configured.
2. Create a private password room. Confirm it is absent from public listings and that wrong passwords, guessed UUIDs, duplicate/team claims and full-room admissions fail. Create a public room; search/filter/page it.
3. Claim distinct teams, copy the invitation, change your team, toggle ready and change host settings. Verify readiness resets on relevant settings changes. Start only with at least two ready connected owners.
4. Simultaneously bid from both browsers. One current-version command succeeds; the other gets a stale snapshot. Confirm opening/base price, increments, rejection at deadline, budget/squad/overseas reservation, highest-bidder exclusion, irreversible pass and server-only resolution. Disconnection alone must not count as pass.
5. Refresh/reconnect and test a duplicate session. The new session controls the team; the old tab shows takeover. Switch network/app foreground and verify full snapshot restoration.
6. Restart the backend during a live bid and during reveal. Confirm exactly one purchase/deduction and synchronized recovery. Leave all browsers disconnected for over two minutes; verify host grace/transfer/pause and authorized return. Repeat against real Postgres to verify actual lock/constraint behavior.
7. Kick an owner in lobby and auction. Confirm blocked rejoining, socket eviction, voice eviction, and preservation of purchased players. Transfer host to another connected owner.
8. Pass all eligible teams through unsold lots, rerun with new IDs, then finish. Full/ineligible squads should automatically complete when nobody can acquire remaining players.
9. Leave completed room, log out/in, inspect saved squads. Choose the purchased XI, distinct captain/vice-captain, save and refresh. A one-player development squad requires only a captain. Purchase amounts must stay unchanged.
10. Send text, try 501 characters, exceed the chat rate limit, load earlier history, reconnect and test scroll/unread behavior. Render HTML as text. Private-room messages must remain inaccessible to outsiders.
11. Run `npm.cmd run test:voice` for generated audio over real two-person and three-person WebRTC calls. Manually test physical microphone permission, muted join, unmute, devices, deafen/leave, disconnect, kick and completion. Repeat with configured LiveKit if using that provider and follow the mobile/device checklist in MOBILE.md. Voice failure must preserve chat/bidding.
12. Check 390px and desktop layouts, keyboard navigation, dialog focus trapping, reduced motion, safe area and keyboard. Install PWA over HTTPS, verify offline app shell and disabled online commands. Build Android APK with SDK/JDK and run iOS on a signed Mac/device.

External-service tests do not pass merely because local adapter tests do. Hosted Auth, RLS, SQL transactions, cloud voice, physical device permissions, signed APK and iOS builds require their corresponding services/toolchains.

Audio/trading acceptance also runs in `test:rejoin`: two owners independently toggle sound, hear instrumented countdown/result cues, restore without replay, reject an offer, accept a player-plus-credit swap, and trade again from completed saved squads. Both purses, current ownership and captain cleanup must update without reloading. Speech utterances are captured using a substitute device speech service; physical playback is a separate check. Test a cash purchase, cancellation, competing offers and depleted budgets manually too. The unit suite covers these edge cases and transaction races. `check:postgres` verifies trade custody in JSONB and normalized purchase rows inside a rolled-back synthetic transaction. See [audio/trade rules](AUDIO-TRADES.md).

`npm.cmd run test:rejoin` runs a separate local instance on ports 3002/5175 with Supabase/Postgres variables explicitly disabled for the test processes. It verifies closing a purchased team's auction tab, finding a full private running room on Home, reopening it with the same budget/team/purchases, and rejoining via the invitation without reselecting a team. It does not modify the configured Supabase database.

The sports interface checks also exercise franchise selection and taken/disconnected owners, reduced motion, the player stats drawer, retained chat drafts and unread counts, a crowded chat, missing portraits/statistics, long names and a shortened composer viewport. Lobby and auction screenshots cover 1440×900, 1280×720, 390×844 and 360×800. The isolated suite also runs the complete purchase/result/saved-lineup flow. Its artifacts live separately under `.runtime/rejoin-results`; avoid sharing that output directory with other browser runs.

Player data shown in the auction acceptance tests comes from the actual local catalog adapter through a deterministic read-only route fixture. Room APIs and sockets remain real. Unit tests separately verify imported data, auction rules, stat presentation, precise credit inputs and contrast for every imported team colour. See [UI.md](UI.md) for component and asset details and the remaining physical-device checks.
